# Examples

Runnable sanity checks for the library, in increasing order of detail. Each
is a plain script, not a notebook, so it can be run in CI or from the command
line as a regression check on the modelling code. The full source for each
is in [`examples/`](https://github.com/wizmik12/gpcrowdkit/tree/main/examples)
in the repository.

## [`01_quickstart.py`](https://github.com/wizmik12/gpcrowdkit/blob/main/examples/01_quickstart.py)

End-to-end fit on a deliberately hard synthetic crowd (only half the workers
reliable, three annotations per item). Asserts that the fitted model beats
plain majority vote, and prints the ELBO decomposition and the mean absolute
error of the recovered worker confusion matrices.

## [`02_compare_annotator_strategies.py`](https://github.com/wizmik12/gpcrowdkit/blob/main/examples/02_compare_annotator_strategies.py)

Trains the same latent GP against the same data with each of the three
shipped [`AnnotatorModel`](api/annotators.md) strategies in turn -- the
demonstration that they really are interchangeable behind `GPCrowdModel`,
with only the one line that constructs `annotator=` changing.

## [`03_diagnostics_plots.py`](https://github.com/wizmik12/gpcrowdkit/blob/main/examples/03_diagnostics_plots.py)

Plots the ELBO decomposition (checking that the `latent` term does not
flatline while `crowd` climbs -- the characteristic crowdsourcing failure
mode) and true-vs-recovered confusion matrices, saved to `examples/output/`.
Requires `pip install -e ".[examples]"` for `matplotlib`.

## [`04_compare_moons_dataset.py`](https://github.com/wizmik12/gpcrowdkit/blob/main/examples/04_compare_moons_dataset.py)

Runs the same comparison as `02_compare_annotator_strategies.py`, but against
the synthetic "moons" dataset generated by [`data/moons.py`](https://github.com/wizmik12/gpcrowdkit/blob/main/data/moons.py),
where annotator noise depends on *where* an item sits in feature space
(spammer/adversarial regions, systematic class bias) rather than being
constant per worker. It also scores every model on a held-out test split with
no annotations at all, which majority vote has no way to address -- the
generalisation only the latent GP can attempt. Requires
`pip install -e ".[data]"` for `scikit-learn` and `pyyaml`.

## [`05_compare_ai4skin_dataset.py`](https://github.com/wizmik12/gpcrowdkit/blob/main/examples/05_compare_ai4skin_dataset.py)

Runs the same comparison as `04_compare_moons_dataset.py`, but against
[AI4SkINv2-2](https://github.com/wizmik12/gpcrowdkit/blob/main/data/ai4skin.py),
a *real* crowdsourcing dataset: skin-lesion whole-slide images graded 0-5 by
up to 10 pathologists, with features mean-pooled from per-slide bags of patch
embeddings (CONCH/PLIP/UNI/VGG16IN). Like the moons dataset it ships a
held-out test split with no annotations, but it also ships its own
precomputed Dawid-Skene, GLAD and MACE aggregations of the same annotations,
so this script benchmarks the crowd model against those established methods
too, not only against a recomputed majority vote. Requires
`pip install -e ".[data]"` for `pyyaml`, and a local checkout of AI4SkINv2-2
(path configured in `data/ai4skin.yaml`).

## Running them

```bash
./run.sh examples/01_quickstart.py
```

`run.sh` configures the project's virtualenv and GPU library paths; run the
script directly with your own interpreter if you manage the environment
differently.
